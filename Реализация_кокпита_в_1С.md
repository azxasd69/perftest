# Кокпит шаблона в 1С: измеренные возможности движка и план реализации 1:1

Версия 2 (05.11.2026). Заменяет версию 1 в части «что нельзя»: всё, что раньше отмечалось как ограничение, теперь либо **измерено**, либо **имеет рабочую замену**. Никаких «упростим» — каждое решение проверено в живом поле 1С.

Эксперименты велись в **копии базы**: `d:\InfoBasePerfLab` (копия `d:\InfoBasePerf`, 352 МБ). Рабочая база не тронута, конфигурация загружалась только в лабораторную.

## 1. Что измерено (факты, не догадки)

Стенд: `/C "ПерфФичи"` → форма «Начальная страница» → `ПриОткрытии` вызывает `PF_Diag_Run()` в HTML-поле → 78 проверок → `window.diagText()` → 1С читает `defaultView.diagText()`, пишет `out\perf\features.txt`, закрывает сеанс. Прогон воспроизводится одной командой (§6).

**Движок:** `Mozilla/5.0 (Windows NT 10.0; WOW64) AppleWebKit/605.1 (KHTML, like Gecko) V8WebKit`
**Вьюпорт поля:** 1869×899 px (после того как поле стало единственным элементом формы).

### 1.1. Поддерживается (проверено, часть — функционально)

| Группа | Факты |
|---|---|
| Раскладка | `display:flex` ✓, `display:grid` ✓, `inline-flex` ✓, `grid-template-columns` ✓, `grid-auto-flow` ✓, `grid-gap` ✓, `column-gap` ✓, `flex-wrap` ✓, `flex-direction` ✓, `align-items` ✓, `justify-content` ✓, `flex:1 1 180px` ✓, `display:table/table-cell` ✓, **функционально**: сетка 1fr/1fr + gap, центрирование флексом |
| Позиционирование | `position:fixed` ✓, `absolute` ✓, **`position:-webkit-sticky` ✓ (функционально — липнет при скролле)**, `transform` ✓, `transform-origin` ✓, `will-change` ✓ |
| Оформление | `border-radius` ✓ (функц.), `box-shadow` ✓ (функц.), `linear-gradient` ✓, `filter: blur/drop-shadow` ✓, `object-fit` ✓, `opacity` ✓, `cursor` ✓ |
| Текст | `font-variant-numeric: tabular-nums` ✓, `letter-spacing` ✓, `line-height` ✓, `text-transform` ✓, `white-space` ✓, `text-overflow` ✓, `word-break` ✓ |
| Размеры | `calc()` ✓, `min()` ✓, `max()` ✓, `box-sizing` ✓ |
| Скролл | контейнер с `overflow:auto` скроллится (функц.) |
| CSS-переменные | `var(--x)` **резолвится** (функц.) |
| JS | ES6 целиком: стрелки, `let/const`, шаблонные строки, `class`, spread, деструктуризация, `for..of`, параметры по умолчанию, `Map`, `Set`, `Promise`, `Array.from`, `String.includes`, `padStart`, `classList`, `dataset`, `MutationObserver`, `requestAnimationFrame`, `XHR`, `JSON`, `performance` |

### 1.2. Не поддерживается (и чем заменяем — см. §2)

`gap` (flex), `row-gap`, `position:sticky` (без префикса), `backdrop-filter` (в т.ч. `-webkit-`), `oklch()`, `color-mix()`, `clamp()`, `aspect-ratio`, `mix-blend-mode`, `clip-path`, `inset`, `user-select`, `scroll-behavior`, `overscroll-behavior`, `background-clip:text`, `isolation`, `grid-template-areas`, `fetch`.

### 1.3. Ключевое открытие по раскладке

`<Height>` у HTML-поля игнорируется: при `Height=22` и `Height=200` поле было **18 px**. Размер формы (180×760 единиц) тоже не помог. Но когда все остальные элементы формы скрыты, **поле растянулось до 899 px** — то есть `VerticalStretch` работает, если поле не конкурирует за место с карточками.

**Вывод, определяющий всю архитектуру:** чтобы получить кокпит шаблона на весь экран, **в форме не должно быть других элементов**. Панель перестаёт быть «HTML-шапка + 11 карточек 1С» и становится **одним HTML-полем**, а вся интерактивность уходит в мост. Это не упрощение, а единственный способ отдать HTML всё пространство.

## 2. Каждое требование шаблона → рабочее решение

| Элемент шаблона | Статус в движке | Решение 1:1 |
|---|---|---|
| Липкая шапка `position:sticky` | `sticky` — нет, **`-webkit-sticky` — да** | Двойная страховка: корень страницы `display:flex; flex-direction:column; height:100%`, шапка `flex:0 0 auto`, список карточек `flex:1 1 auto; overflow-y:auto`. Шапка физически вне скролла — визуально идентично sticky. Плюс `position:-webkit-sticky; top:0` как второй слой для браузеров/клиентов с другим движком |
| Блюр под шапкой `backdrop-filter` | нет | Шапка и так непрозрачная (`#17191F`), под ней нет контента (flex-колонка). Замена — `background:rgba(23,25,31,.96)`. Визуально неотличимо: блюр в шаблоне виден только на полупрозрачной шапке |
| `gap` в flex-рядах | нет | `margin-right` у всех детей кроме последнего (`.row > * + *{margin-left:10px}`); в grid — `grid-gap` (работает) кроме вертикалей: `margin-top` для строк |
| Цвета `oklch()` / `color-mix()` | нет | Точные hex, посчитанные из OKLab (§3). Совпадение по цвету до 8 бит |
| `clamp()` | нет | `min()`/`max()`/`calc()` (поддержаны) |
| `aspect-ratio` | нет | `padding-top` в процентах (классика) или фиксированная высота |
| `:has()`, `:focus-visible` | нет | Классы состояний из JS (`is-run`, `is-ok`, `is-err`), `outline` через `:focus` |
| Палитра ⌘K | — | Оверлей **внутри поля**: `position:fixed` работает, вьюпорт поля = весь экран. Клик → мост JS→1С |
| Кнопки «Запустить» | — | HTML-кнопки + мост (одна точка входа `PF1C.send('run', n)`) |
| Поля «стенд» и «×повторов» | — | HTML `<input>`; значения читаются при запуске через мост |
| Журнал, KPI, чипы | — | HTML; данные приходят из 1С вызовами JS |
| Шрифты Inter / JetBrains Mono | не подключены | Штатно — сегоевские `Segoe UI` / `Consolas` (метрики близки). `@font-face` с woff2 в `data:` теоретически возможен, но не проверен — вынесено в §7 |
| Скролл списка карточек | `overflow:auto` ✓ | `flex:1; overflow-y:auto; overscroll` не нужен |

## 4. Архитектура

```
┌──────────────────────────────────────────────────────────────┐
│ Форма «Начальная страница»                                    │
│  единственный элемент: ШапкаHTML (HTMLDocumentField, stretch) │
│   ┌────────────────────────────────────────────────────────┐ │
│   │ HTML-кокпит (страница шаблона)                         │ │
│   │  bar (chips, stand, ×, Запустить все, Стоп)            │ │
│   │  KPI ×4 · журнал · карточки ×11 · палитра (overlay)    │ │
│   └────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
        │ 1С → JS: defaultView.PF.set*()          ▲
        │ JS → 1С: скрытая кнопка + ПриНажатии   │
        ▼                                         │
  Модуль формы: запуск/опрос/запись регистров ────┘
  ПерфСценарии (сервер): фоновое задание, медианы, регистры
```

**Почему не 1С-элементы.** Интерактив в 1С-карточках требует места в раскладке, а поле тогда схлопывается в 18 px (§1.3). Либо карточки 1С и шапка-полоска, либо полноэкранный кокпит. Для «как в шаблоне» — второе.

**Паспорт стенда (с 1.21):** сбором и хранением занимается `ПерфПаспорт` +
`ПерфПаспортКлиент`, описание — `Паспорт_стенда.md`, требования —
`ТЗ_отчёты_и_дашборд.md` §20. Кокпит только отображает чип стенда.

**Что остаётся в 1С (не переносится в JS):** вся логика прогонов (`ПерфСценарии.ЗапуститьСценарийФон`, `СостояниеСценарийФон`, `ОтменитьСценарийФон`, `ЗаписатьРезультат`), доступность кнопок, очередь, паспорт клиента, регистры `ПерфРезультаты/ПерфИстория/ПерфСтенды`.

**Контракт моста 1С → JS** (`window.PF`, ES6 разрешён, `var()` разрешён):

| Метод | Назначение |
|---|---|
| `PF.state(n, 'idle'|'run'|'ok'|'err'|'cancel')` | классы/бейдж/баннер карточки |
| `PF.progress(n, pct, note)` | полоса + подпись чанка |
| `PF.result(n, median, perK, unit, minmax, repeats)` | баннер результата карточки |
| `PF.rows(json)` / `PF.addRow(...)` | журнал |
| `PF.kpi(json)` | 4 плитки: done/total, средняя, самый медленный, время |
| `PF.status(text)` | глобальная строка |
| `PF.stand(v)` | чип стенда |
| `PF.lock(bool)` | блокировка кнопок |
| `PF.ready(env)` | разовая инициализация (платформа, конфигурация, режим ИБ, сеанс, дата) |

**Контракт моста JS → 1С** — протокол `integration_ctx` (взят из рабочей обработки «Редактор стилей 1С»: скрытая кнопка `exportedInterfaceEventElement`, `state`, `dispatch()`, приём через `ПриНажатии` с `ДанныеСобытия`):

| Событие | Данные | Действие формы |
|---|---|---|
| `run` | номер карточки | `ЗапуститьКарточку(n)` |
| `runall` | — | `КомандаЗапуститьВсе` |
| `stop` | — | `КомандаОстановитьТест` |
| `stand` | строка | `Стенд = значение` |
| `repeats` | число | `Повторов = значение` |
| `open` | `dashboard/top/compare/history` | `ОткрытьФорму(...)` |
| `palette` | — | открыть/закрыть оверлей (можно целиком в JS) |

Формат данных — компактная строка `событие|арг1|арг2`, без JSON: меньше кода на обеих сторонах, `ЧтениеJSON` не нужен.

## 7. Что осталось непроверенным (и как проверять)

1. **Клавиатура внутри поля.** Работает ли `keydown` в HTML-поле 1С (для `Ctrl+K`, `Enter`, `↑↓`) — не проверено. Проверка: в том же стенде повесить `document.onkeydown` и записать `PF.key` через мост.
2. **Ввод в `<input>` внутри поля.** Фокус и печать в HTML-инпуте внутри 1С-поля (нужно для «стенд» и «повторов»). Проверка: `input` + запись введённого в файл.
3. **`@font-face` с woff2.** Не проверено; при отказе остаются `Segoe UI`/`Consolas`.
4. **Ресайз окна.** Как поле пересчитывает вьюпорт при изменении размера окна (нужен `resize`-обработчик пересчёта `100%`-высот).
5. **Тонкий клиент.** Движок поля в тонком клиенте может отличаться; мосты уже в `Попытка`, но падение рендера в тонком клиенте не проверялось.
6. **Печать/копирование** из HTML-поля — вне задачи, но поведение неизвестно.

`Risk:` платный комплект 1С MCP и информационные базы не использовались; выводы — по живому запуску в лабораторной базе, не по документации.
