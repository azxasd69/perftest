# Закрепление шапки кокпита

Документ описывает, почему шапка кокпита не прилипала к верху, какие варианты
закрепления существуют в поле HTML 1С и что в итоге сделано. Замеры сняты
зондом на копии базы 07.11.2026, платформа 8.3.27.2342.

## 1. Задача

Шапка кокпита (бренд, переходы по отчетам, поля, «Меню», пуск и стоп) должна
оставаться на месте, пока пользователь прокручивает карточки сценариев вниз.
Прокручиваемый контент должен уходить под шапку.

## 2. Чем мерили

Зонд - скрипт, вставленный в страницу кокпита в отдельной копии конфигурации
(`scratch\src-probe3`, база `scratch\ib-probe3`). Скрипт меряет геометрию через
`getBoundingClientRect` и отправляет строки в 1С мостом `PF1C.send`; форма
пишет их в `%TEMP%\pf-cockpit.log`. Ничего в рабочей базе при замерах не
менялось.

## 3. Что показали замеры

| Факт | Значение | Вывод |
|---|---|---|
| `document.scrollingElement` | `BODY` | прокручивается документ, а не внутренний блок |
| `documentElement.scrollHeight` | 0 | у `html` нет собственной высоты |
| `body.scrollHeight` = `body.clientHeight` | 609 = 609 | тело не переполнено по своей модели |
| `window.scrollY`, `body.scrollTop` | всегда 0 | JS не видит прокрутку |
| `window.scrollTo(0,400)`, `body.scrollTop=400` | смещение осталось 0 | программно прокрутить нельзя |
| Элементы с собственным переполнением | 1 (`NAV.side`, 236 px) | внутренний `overflow` в движке работает |
| `position:fixed` (тестовый блок) при прокрученной странице | `top=0`, `left=0` | **фиксируется к видимой области** |
| `.bar` (обычный блок) в тот же момент | `top=-384` | контент уехал вверх, как и положено |
| `.side`, `.stat` | `position:fixed`, `top=0` / низ | боковое меню и полоса состояния держатся |
| `position:sticky` (прошлый замер) | значение принято, липкости нет | скроллер находится вне DOM |

Главное: **прокрутку выполняет сам движок поля, а не CSS-скроллер**. Поэтому
`sticky` не к чему липнуть (у него нет прокручиваемого предка), а `fixed`
работает - он привязан к видимой области, что и подтвердил тестовый блок,
оставшийся в `top=0` при сдвинутом на 384 px контенте.

## 4. Варианты

| # | Вариант | Что требуется | Итог |
|---|---|---|---|
| A | Только HTML | - | невозможен: закрепление это поведение раскладки, а не разметки |
| B | CSS `position:sticky` | одна строка CSS | не работает: движок принимает значение и не липнет (замер) |
| C | CSS `position:fixed` + распорка фиксированной высоты | CSS | работает, но распорка не знает реальную высоту шапки: при переносе строки на узком окне контент либо уезжает под шапку, либо получает лишний зазор |
| D | `fixed` + распорка, высоту ставит скрипт | CSS + 4 строки JS | **выбрано**: точная высота при любом переносе и ресайзе |
| E | Свой скролл-контейнер: шапка в потоке, контент в блоке `overflow:auto;height:...` | CSS + перестройка страницы | теоретически возможно (внутренний `overflow` движок поддерживает), но появляется второй скроллбар рядом со штатным, а высоту контейнера надо знать точно - хрупко |
| F | Два поля HTML на форме 1С: шапка в отдельном поле фиксированной высоты, контент ниже | переделка формы | не закрепляет, а «выносит» шапку из прокрутки: работает при любом движке, но шапка и страница перестают быть одной сборкой, а `Height` у поля HTML ведёт себя непредсказуемо (проверяли ранее) |
| G | Шапка на элементах формы 1С (кнопки, поля), HTML только контент | переделка дизайна | надёжно, но теряется весь вид шапки: чипы, сегмент, тема |
| H | Не закреплять, оставить как есть | - | отвергнуто: на длинном списке карточек кнопки пуска и поля уезжают из вида |

Почему не E: штатная прокрутка поля уже работает, и вторая, внутренняя, даст
два скроллбара и «залипание» колеса в зависимости от того, где курсор.

Почему не F: разрез страницы на два поля требует согласовывать высоту шапки
между 1С и HTML при каждом переносе строки, а `Height` у поля HTML в этой
платформе игнорируется (проверено ранее на панели).

## 5. Что сделано

Вариант D, минимальными средствами.

1. `ПерфUI.Стили`:
   - `.bar-single` стал `position:fixed; left:284px; right:0; top:0; z-index:45`
     с прямыми верхними углами и скруглением снизу, тень отделяет шапку от
     уезжающего под неё контента;
   - `.bar-in` - внутренняя колонка `max-width:1500px; margin:0 auto` с теми же
     отступами, что у `.wrap`, поэтому шапка выровнена по карточкам при любой
     ширине окна;
   - `body.pf-collapsed .bar-single{left:76px}` - при свёрнутом меню шапка
     сдвигается вместе с контентом;
   - `#barspace{height:60px}` - стартовая высота распорки до первого замера.
2. `ПерфКокпит.Страница`: содержимое шапки обёрнуто в `.bar-in`, сразу после
   `</header>` вставлена распорка `<div id='barspace'></div>`.
3. `ПерфКокпит.СкриптКокпита`: функция `pfBar()` ставит распорке высоту
   реальной шапки; вызывается по `load`, по `resize` и дважды по таймеру
   (150 и 700 мс), потому что шрифты и перенос строки успевают измениться
   после первой отрисовки.

Отчеты не тронуты: у них своя разметка `.bar` без класса `bar-single`, поэтому
их шапки остались в потоке.

## 6. Проверка

| Проверка | Результат |
|---|---|
| BSL LS 1.0.7 | 0 ошибок, 0 предупреждений |
| Загрузка конфигурации (8.3.27.2342) | код 0 |
| Смоук форм | 6/6, кокпит 48 052 симв. |
| Зонд: положение шапки | `position:fixed`, `top=0`, `z=45` |
| Зонд: распорка | высота 99 px = высоте шапки при узком окне (две строки) |
| Зонд: выравнивание | `barLeft=284`, `wrapLeft=284` - шапка по колонке контента |
| Снимок «контент под шапкой» | контент уходит под непрозрачную шапку, шапка на месте |
| Снимок со свёрнутым меню | шапка начинается с 76 px, рейл 60 px |

Не проверено живой прокруткой колесом в окне 1С: в агентском шелле окно не
снимается, а программная прокрутка в этом движке не работает (`scrollTo` -
no-op). Опора на два факта: тестовый `position:fixed` блок остался в `top=0`
при сдвинутом контенте, и боковое меню с полосой состояния (тоже `fixed`)
ведут себя так же и в живой работе замечены как закреплённые.

## 7. Риски и что смотреть

- **Перенос строки в шапке.** На узком окне шапка занимает две строки; распорка
  это учитывает, но между первым расчётом и загрузкой шрифтов возможен
  однопиксельный сдвиг. Лечится повторным вызовом `pfBar()` (уже стоит).
- **Ресайз окна 1С.** Обновление распорки висит на `resize`; если движок его не
  пришлёт, высота останется от прошлой ширины - тогда поможет `pfBar()` по
  таймеру при следующем открытии.
- **Полоса прокрутки.** Шапка тянется до `right:0` и может заходить под
  вертикальную полосу прокрутки на 15-17 px; на вид не влияет.
- **Отчеты.** Их шапки по-прежнему уезжают при прокрутке. Если нужно так же -
  это отдельная правка: тем же способом, но для `.bar` в `ПерфОтчетыHTML`.

## 8. Откат

Одна правка в `ПерфUI.Стили`: вернуть `.bar-single` в поток
(`position:relative`, без `left/right/top`, `display:flex`, `padding:10px 12px`)
и удалить правило `.bar-in`; распорка и `pfBar()` безвредны.
