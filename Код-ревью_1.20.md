## 2. BSL — замечания

### Высокий приоритет

1. **HTML собирается конкатенацией строк внутри BSL.** `ПерфКокпит` (~23 КБ), `ПерфUI` (~20 КБ), `ПерфОтчетыHTML`. Любая кавычка внутри JS/HTML обязана быть удвоена, обратный слэш запрещён. Инцидент подтверждён: `ПерфКокпит (198,67) Ожидается ')'` — сеанс не стартовал вовсе.
   Рекомендация: вынести статические части в макеты (`ОбщийМакет`) и подставлять параметры; строковую сборку оставить только для данных.

2. **Прямые вызовы в поле HTML из клиентских обработчиков.** `Элементы.ШапкаHTML.Документ.defaultView` вызывается из таймера — это дало зависание интерфейса при старте прогона (лечение: вызов снят). Остались ещё три места обращения к мосту (`ОпросМоста`, результат карточки, тема).
   Рекомендация: единая точка «отложенной отправки» — таймер только складывает команды в очередь формы, применяет их отдельный однократный обработчик.

3. **Отсутствие единой обработки ошибок моста.** Обращения обёрнуты в `Попытка` с пустым `Возврат` — ошибка глотается без следа.
   Рекомендация: писать текст в лог (уже есть `ЗаписатьСтрокуВЛогКокпита`) перед `Возврат`.

### Средний приоритет

4. **Дублирование стилей.** База токенов живёт в `ПерфUI.Стили`, но `ПерфКокпит.СтилиКокпита` содержит свою копию базовых правил, а `ПерфUI.СтилиСветлая` перекрывает их `!important`. Три слоя каскада — хрупко.
   Рекомендация: оставить в `СтилиКокпита` только кокпит-специфику (состояния, палитра команд), базовые правила удалить.

5. **Магические числа и строки.** Ширины (`220px`, `60px`, `132px`), интервалы (1 с), цвета в тексте правил. При смене темы или масштаба правки идут в нескольких местах.
   Рекомендация: вынести в функции-константы модуля (`ШиринаРельса()`, `ЦветАкцента()`), тогда светлая тема перестанет дублировать значения.

6. **`ТекущаяДата()` в клиентском коде** с подавлением правила `DeprecatedCurrentDate`. Формально верно (в клиенте нет `ТекущаяДатаСеанса`), но дата в журнале может расходиться с серверной.
   Рекомендация: передавать дату с сервера вместе с результатом.

### Низкий приоритет

7. **`УстановитьДоступностьКнопок` — пустая процедура.** Осталась как совместимость с вызовами. Либо удалить вместе с вызовами, либо оставить комментарий (сейчас комментарий есть).

8. **Неиспользуемые константы в JS.** `PFList` (компонент списков) удалён из модуля при откате — проверить, что в `ПерфUI` не осталось мёртвых функций.

## 3. CSS — замечания

1. **`!important` в светлой теме** — 40+ правил. Неизбежно при перекрытии без CSS-переменных (движок их не поддерживает), но повышает риск: любое новое правило в базе не сможет переопределить светлое.
2. **Порядок вставки важен.** Стили рейла и тела отчёта добавляются в тело документа после `<body>`, поэтому каскад зависит от места вставки, а не от специфичности.
3. **`padding` тела отчёта задан дважды** — в `ПерфUI` (`.pf-body`) и в `ПерфОтчетыHTML`; значения синхронизированы вручную (90 px).
4. **Анимации продублированы с `-webkit-`** — правильно для QtWebKit, но при переходе на 8.5 дубли станут лишними.
5. **Горизонтальная прокрутка не побеждена**: `overflow-x:hidden` на `html` и `body` не убирает скроллбар самого поля — это ограничение движка, не вёрстки.

## 4. HTML — замечания

1. Разметка собирается вручную, валидатора нет: ошибка в теге проявляется только визуально.
2. **Возможен дубль `id`**: кнопка темы создаётся скриптом, если её нет в разметке; в кокпите она уже есть в шапке — проверка `if(!document.getElementById(...))` защищает, но при двух полях на одной странице (отчёт + панель) возможны коллизии.
3. Инлайн-обработчики (`onclick='PF1C.send(...)'`) — работают, но не отделены от данных; при экранировании текста в подписи кнопки нужна аккуратность.

## 5. JS — замечания

1. Глобальные объекты: `PF1C`, `PFTheme`, `PFNav`, `PFThemeToggle` — пространство имён не изолировано; для одного приложения приемлемо.
2. `localStorage` в `try/catch` — верно: в поле 1С хранилище может быть недоступно.
3. Тема реализована вставкой/удалением тега `<style>` — единственный надёжный способ; `media` и `disabled` движок не пересчитывает (проверено).
4. **Прогресс** ограничен 99 % до завершения, анимация отключена — поведение честное, но шаг дискретный.
5. Нет защиты от двойного клика по «Запустить» на разных карточках: блокировка есть только у кнопок после старта.

## 6. Функциональные дефекты, известные на релиз

1. Кнопки «Сформировать» / «Сбросить к сеансу» в HTML-шапке отчётов отправляют команды, **обработчиков нет** — нужен серверный вызов вне контекста команды.
2. Сетка карточек стендов в дашборде не растянута на всю ширину.
3. Светлая строка заголовка клиента 1С — вне конфигурации (обход: сдвиг окна).
4. Горизонтальный скроллбар HTML-поля.
5. Этапы 7–8 (списки, формы элементов, `ПерфРаннер`) — не начаты, приостановлены по решению.

## 7. Вердикт

**Релиз 1.20 допустим как внутренний:** кокпит и дашборд работают, гейты чистые, прогон сценариев проходит. Для внешнего выпуска блокируют: пункты 6.1 (кнопки отчётов) и 6.2 (сетка), а также отсутствие визуальной проверки трёх отчётов.
