# План: перенос оформления шаблона `index-v3.html` в конфигурацию PerfTest

Версия 1 (06.11.2026). Задача: привести **всё** оформление 1С — цвета, панель, формы списков, формы отчётов, документы, обработки — к виду шаблона кокпита. Работа ведётся на рабочей базе `d:\InfoBasePerf` (конфигурация 1.18), эксперименты — на копиях.

Документ опирается на: `Реализация_кокпита_в_1С.md` (измерения движка HTML-поля), `Инструкция_агента_HTML-поле_и_проверка_отчётов.md` (регламент проверки и обязательная обёртка `<html>`), исходный код обработки «Редактор стилей 1С» (механизм стилей, §2), документацию платформы по параметру `/Theme` (§2.2).

## 2. Что подтверждено фактами

### 2.1. Стиль расширением: РАБОТАЕТ (проверено на рабочей базе 06.11.2026)

Рабочий рецепт (всё ниже проверено загрузкой в `d:\InfoBasePerf`, код 0, и снимком экрана):

1. **Расширение-дополнение**: корневой `Configuration` — `ObjectBelonging = Adopted` (а не `Own` — иначе «Загрузка не должна менять принадлежность основного объекта конфигурации»), обязателен непустой `InternalInfo` (7 `xr:ContainedObject`, копируются из основной конфигурации), `ConfigurationExtensionPurpose = AddOn` (с `Customization` приложение падает), `NamePrefix`, `ConfigurationExtensionCompatibilityMode`.
2. **Объект стиля**: `Styles/<Имя>.xml` (обычный `Style`, без дочерних элементов) + тело `Styles/<Имя>/Ext/Style.xml`.
3. **Тело стиля** — корень `Style` в пространстве `http://v8.1c.ru/8.3/xcf/extrnprops` с `version="2.20"`; элементы — `<Item name="AccentColor"><Color>#C4F252</Color></Item>`. Имена — только английские (`AccentColor`, `ActivityColor`, `NavigationColor`, `AuxiliaryNavigationColor`, `ImportantColor`).
4. **Цвет — без префикса**: `<Color>#C4F252</Color>` работает, `<Color>web:#C4F252</Color>` отвергается с пустым текстом ошибки (в логе только путь к файлу — это сбивает с толку).
5. В расширении — `<DefaultStyle>Style.<Имя></DefaultStyle>` в свойствах и `<Style><Имя></Style>` в `ChildObjects`.
6. **Загрузка в два шага**: `DESIGNER /F<база> /LoadConfigFromFiles "<каталог>" -Extension <Имя>`, затем отдельно `DESIGNER /F<база> /UpdateDBCfg -Extension <Имя>`. Если добавить `/UpdateDBCfg ... -Extension` в ту же команду — «Ошибка в параметрах командной строки».
7. Имя расширения — латиницей (`PerfStyle`); предопределённые имена в `StyleItem` верхнего уровня запрещены («Недопустимое имя элемента стиля») — только внутри тела стиля.

Результат на рабочей базе: верхняя панель и строка меню стали тёмными (`#17191F`), заголовки карточек получили акцент. Полностью тёмным приложение станет после перевода содержимого форм на HTML (слой B): фон клиентской области Taxi стилевыми цветами не управляется.

### 2.1a. История тупиков (чтобы не повторять)

| Что пробовал | Ответ платформы |
|---|---|
| `Style` + `<ChildObjects><StyleItem>` в основной конфигурации | «Текущее ChildObjects, ожидаемое Style» |
| `StyleItem` верхнего уровня с предопределёнными именами | «Недопустимое имя элемента стиля» |
| Цвета как свойства объекта `Стиль` | загрузка rc=0, цвета молча отброшены |
| Тело с `web:#...` | rc=1, в логе только путь к файлу |
| Расширение с `ObjectBelonging=Own` у корня | «Загрузка не должна менять принадлежность» |
| Расширение с `Customization` | приложение падает при старте |

### 2.1b. Справочно: из чего состоит стиль (подтверждено кодом обработки и справкой)

- объект метаданных — **`Стиль`** (`Метаданные["Стили"]`), свойство конфигурации — **`ОсновнойСтиль`** (XML `DefaultStyle`, значение вида `Style.<Имя>`);
- в файле стиля есть каталог **`StyleItems`**, каждый элемент — отдельный объект `<StyleItem>` с `<Type>` (Цвет/Шрифт) и `<Value>`;
- пять стилевых цветов с точными именами: **`AccentColor`** (ЦветАкцента), **`NavigationColor`** (ЦветНавигации), **`AuxiliaryNavigationColor`** (ЦветДополнительнойНавигации), **`ActivityColor`** (ЦветАктивности), **`ImportantColor`** (ЦветВажного);
- шрифты задаются тремя способами: `kind="StyleItem"`, `kind="WindowsFont"`, `kind="Absolute"` с атрибутами `faceName/height/bold/italic/underline/strikeout/scale`;
- стиль можно поставить **расширением конфигурации** (`КонфигурацияРасширения.ОсновнойСтиль`, `ПринадлежностьОбъекта = "Собственный"`) — то есть без правки основной конфигурации, обратимо.

Практический смысл: панель разделов, акцент кнопок, цвет активности, шрифты интерфейса можно перевести в палитру шаблона **одним объектом метаданных**, а не правкой каждой формы.

### 2.2. Тема клиентского приложения

В 8.5.4 документирован параметр командной строки **`/Theme <тема>`** (руководство администратора, приложение 7; там же `/i85` — интерфейс версии 8.5), а веб-клиент принимает `?theme=dark`. Для 8.3.27 такого параметра в документации нет.

Следствие: **по-настоящему тёмный хром** (окно, панели, поля) достижим на 8.5.4; на 8.3.27 — только стилевые цвета и наши HTML-формы. Проверка — этап 2, на копии базы (8.5.4 поднимает формат файловой базы).

### 2.3. Движок HTML-поля (измерено на живом сеансе, 78 проверок)

- `AppleWebKit/605.1 V8WebKit`; поле при единственном элементе формы — **1869×899 px**;
- есть: flex, grid, `grid-gap`/`column-gap`, `calc/min/max`, `border-radius`, `box-shadow`, градиенты, `transform`, `transition`, `animation`, `filter`, `font-variant-numeric`, `var()`, `position:fixed`, **`position:-webkit-sticky`** (функционально проверено), весь ES6, `MutationObserver`, `rAF`;
- нет: flex-`gap`, `row-gap`, `sticky` без префикса, `backdrop-filter`, `oklch()`, `color-mix()`, `clamp()`, `aspect-ratio`, `fetch`.

### 2.4. Обязательное правило отрисовки отчётов

Поле HTML документа показывает только **полный документ**: значение должно начинаться с `<html`/`<!DOCTYPE`. Иначе платформа трактует текст как адрес и показывает пустую страницу (`Couldn't resolve host name: http://<style>…`). Без этой правки любые работы по стилю отчётов бессмысленны — форма останется белой. Правка одна, в `ПерфОтчетыHTML.РезультатОтчёта`.

## 5. Библиотека `ПерфUI` — чтобы не рисовать одно и то же 12 раз

Общий модуль (сервер) + один общий макет CSS. Состав:

- `Стили()` — весь CSS токенов и компонентов (единственное место правки цвета);
- `Страница(Заголовок, Содержимое, Скрипт = "")` — обёртка `<html><head>…</head><body>…`;
- `Шапка(Чипы)`, `Чип(Метка, Значение, Тон)`, `КПИ(4)`, `Карточка(...)`, `Таблица(Колонки, Строки, Сортировка)`, `Кнопка(...)`, `Поле(...)`, `Палитра()`, `Журнал(...)`;
- `СписокСервер(Метаданные, Отбор, Поиск, Страница)` — выборка + сериализация для HTML-таблицы;
- парный клиентский модуль для моста `PF1C.send(...)` (протокол `событие|арг1|арг2` из `Реализация_кокпита_в_1С.md`).

Правило: ни одна форма не содержит собственного CSS — только вызовы `ПерфUI`. Тогда смена палитры = одна правка.

## 7. Риски и что осталось непроверенным

1. **`/Theme dark` на 8.3.27** — в документации параметра нет; проверка на 8.5.4 (этап 3). Если рабочая платформа остаётся 8.3.27, тёмный хром недостижим: тогда A даёт только цвета и шрифты, а «тёмным» приложение становится лишь в HTML-формах.
2. **Стиль в расширении** — механизм подтверждён кодом Рарус, но применение `ОсновнойСтиль` расширения к нашей конфигурации не проверялось (этап 2).
3. **Пять цветов против палитры шаблона** — платформа раскрашивает ими свои элементы; часть оттенков (полупрозрачные подложки, градиенты) нативно не выражается.
4. **Клавиатура в HTML-поле** (Ctrl+K, Enter) — не проверено; палитра команд может остаться мышиной.
5. **Ввод в `<input>` внутри поля** — не проверено (нужно для стенда/повторов).
6. **Скорость HTML-списков** на больших выборках: пагинация обязательна, иначе 10 000 строк в WebKit-поле деградируют.
7. **Тонкий клиент** — движок поля может отличаться; проверка снимками на каждом этапе.
8. **`ФорматЧисла(0)` возвращает пустую строку** — известный дефект вывода чипов, чинится отдельно.

`Risk:` платный комплект 1С MCP и внешние ИБ не использовались; все утверждения — по живым прогонам и по коду/документации, указанным в §2.
