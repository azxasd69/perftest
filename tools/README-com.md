# COM-коннектор 1С (`V83.COMConnector`) — состояние и работа

Обновлено: 08.11.2026. Диагностика и починка по запросу «COM-коннектор 1С не работает».

## Коротко

Коннектор **исправен и подключён**, но **только для 32-битных процессов**. Причина не в
регистрации как таковой, а в разрядности `comcntr.dll`: в обеих установленных платформах
(8.3.27.2342 и 8.5.4.1306) она x86, как и `1cv8.exe`. Поэтому:

| Процесс | `New-Object -ComObject V83.COMConnector` | Комментарий |
|---|---|---|
| PS 5.1 **x86** (`SysWOW64`) | OK | `CoCreateInstance` → hr = 0 |
| Python 3.12 **x86** (`<python32-dir>`) | OK | через pywin32 |
| PS 5.1 x64, PS 7, Python 3.14 (x64), Node 64 | `0x80040154 REGDB_E_CLASSNOTREG` | 64-битная ветка реестра пуста — так и должно быть |

`TYPE_E_LIBNOTREGISTERED` (0x8002801D) из аудита — вторичный симптом: запись TypeLib жила
только в `HKCU\Software\Classes\TypeLib\{98AC3B5B-…}\1.0\0\win32` со значением `FLAGS=0`,
а CLSID — только в 32-битной ветке HKLM. Класс при этом создавался.

## Что сделано

1. **32-битный хост-интерпретатор**: `<python32-dir>` — Python 3.12.10 embeddable (x86),
   `pip` + `pywin32` внутри папки (`Lib\site-packages`, вшит через `python312._pth`).
   Системные Python 3.14 и вендорский 3.13 не тронуты.
2. **Инструмент**: `tools\com-query.ps1` (обёртка) + `tools\com-query.py` (сам запрос).
3. **Регистрация (вариант B)**: `tools\com-register.ps1 -Apply` — `FLAGS=128`
   (`LIBFLAG_FHASDISKIMAGE`) в ключе TypeLib и справочный ключ
   `HKCU\Software\Classes\1C\1Cv8\ComConnector32`; бэкап в `tools\com-registry-backup\`,
   журнал `tools\com-registry-added.json`, откат `-Revert`.
4. **env-check**: строка `1c-com-connector`.

## Использование

```powershell
# сведения о конфигурации и счётчики объектов метаданных
pwsh -File tools\com-query.ps1 -Base d:\InfoBasePerf -Info

# read-only запрос (по умолчанию JSON, -Table — TSV)
pwsh -File tools\com-query.ps1 -Base d:\InfoBasePerf `
    -Query "ВЫБРАТЬ Стенд, Сценарий, ДатаЗамера, МедианаМс ИЗ РегистрСведений.ПерфРезультаты" -MaxRows 5
```

Прямой вызов без обёртки: `<python32-dir>\python.exe tools\com-query.py --base <каталог ИБ> --query "..."`.

Разрешены только запросы `ВЫБРАТЬ` (запись в ИБ через инструмент невозможна); для
диагностики `--raw` снимает проверку. База с аутентификацией: `-User` и полная строка
соединения через переменную окружения `ONEC_CONNINFO` (`Usr="…";Pwd="…"`).

## Грабли 1С 8.3.27 (проверено вживую)

1. **`Выгрузить()` → ТаблицаЗначений** — рабочий способ читать строки. Построчный курсор
   (`Выполнить().Выбрать()`, `Следующий()`, `Колонки`) из win32com недоступен: 1С отдаёт
   объекты без `ITypeInfo`, и в дисп-таблице есть только часть членов (`Следующий` есть,
   `Колонки` нет).
2. **`ПЕРВЫЕ N` в запросе даёт ложные пустые выборки.** «ВЫБРАТЬ ПЕРВЫЕ 3 Наименование ИЗ
   Справочник.Номенклатура» → 0 строк, без `ПЕРВЫЕ` → 1 (реальная). Не использовать
   `ПЕРВЫЕ` в диагностических запросах; ограничивать вывод `-MaxRows`.
3. **Автопривязка по имени класса ненадёжна**: `gencache.EnsureDispatch` на TLB коннектора
   подставляет чужие DISPID (`ВЫБРАТЬ` уходил как `QueryInterface`). Инструмент вызывает
   члены явно через `GetIDsOfNames`/`Invoke`.
4. **Даты из 1С** приходят как `datetime` с UTC — при сравнении с локальным временем
   (`ТекущаяДатаСеанса`) учитывать смещение (MSK +3).

## Закрыто попутно: аудит P1-2 (даты в отчётах)

Запрос к `РегистрСведений.ПерфРезультаты` (`d:\InfoBasePerf`) — 22 записи:

* 5 записей `2026-11-08 05:22:17`, 3 — `05:22:13` и т. д. — автопрогон **прошёл** и записал
  данные (локально 05:22 MSK);
* 11 записей `2026-11-07 20:07–20:08` — прошлый прогон (локально 20:07 MSK, те же сутки).

То есть «даты на сутки назад» — разница в 9 часов между записями, а не сдвиг даты:
свежие строки датированы верно. Гипотеза «`ДатаЗамера` не обновляется при перезаписи по
ключу» не подтверждается — обе группы присутствуют в регистре отдельно.

Оговорка: это выборка из `ПерфРезультаты`; если на страницах отчётов действительно
показывались старые даты, дело в порядке строк в HTML-выводе, а не в самих данных —
проверять там (запросы того модуля с датами как раз прошли).

## Ограничения и риск

* **Проверка через 64-битные инструменты недоступна by design**: для Python 3.14, PS 7 и
  Node коннектор не заработает без 64-битной `comcntr.dll` (в x86-установке платформы её
  нет). Если нужен именно x64-хост, придётся ставить 64-битные компоненты 1С — отдельная
  задача.
* Интерактивные GUI-интеграции (Excel, Word) на этой машине не проверялись: 64-битные
  Office/VBA упрутся в ту же разрядность; 32-битные — будут работать.
* COM-коннектор требует лицензию: комьюнити-лицензия активна (`C:\ProgramData\1C\licenses`),
  `Connect` к файловым базам проходит.

## Откат (полный)

```powershell
pwsh -File tools\com-register.ps1 -Revert     # вернуть FLAGS и удалить справочный ключ
Remove-Item <python32-dir> -Recurse -Force      # удалить 32-битный Python
```

Код в ИБ ничем не менялся: все операции через коннектор — чтение.
