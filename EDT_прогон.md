### Замечания по CLI

- Вывод `1cedtcli` идёт в UTF-16 без BOM, причём порядок байт встречается разный;
  читать напрямую из PowerShell нельзя - получается мусор. Обёртка `scratch\edt.py`
  определяет кодировку по доле читаемых символов (UTF-16LE/BE, UTF-8, cp866).
- Список проектов в `--project-list` принимается **только** JSON-массивом в одной
  строке: `["путь1" "путь2"]`. Отдельные аргументы и запись через запятую дают код 204
  «Не найден вариант вызова команды».
- `import --project` (вариант 1) импортирует готовый EDT-проект, а не XML-выгрузку;
  для XML нужен вариант с `--configuration-files`. Повторный импорт в уже
  существующий проект запрещён (код 204 «Проект с именем … уже существует») -
  обновление делается копированием изменённых `Module.bsl` в проект.

## 3. Найденная и исправленная ошибка

`ОбщийМодуль.ПерфПаспортКлиент.Модуль`, строка 52:

```
Функция 'ИмяКомпьютера' не определена [Web-клиент]
```

`ИмяКомпьютера()` есть в толстом и тонком клиенте, но не в веб-клиенте: для web
модуль не компилировался, и клиентский паспорт стенда переставал собираться целиком,
хотя в толстом клиенте работал.

Исправлено блокировкой препроцессора:

```bsl
// ИмяКомпьютера() есть в толстом и тонком клиенте, но не в веб-клиенте:
// там ключ не собирается, иначе модуль не компилируется для web.
#Если НЕ ВебКлиент Тогда
	Попытка
		Части.Добавить("Компьютер=" + СокрЛП(ИмяКомпьютера()));
	Исключение
		ИгнорируемаяОшибка = ИнформацияОбОшибке();
	КонецПопытки;
#КонецЕсли
```

Проверки после правки: `bsl-check` 0, `load`/`check` 0, смоук 6/6, повторный
прогон EDT - ошибок нет.

либо принять как исключение (в EDT это делается подавлением маркера), либо отдельно
переписать `ШагЗапросы` на пакетный вызов с кэшем.

## 5. Как повторить

```powershell
# 1. Импорт конфигурации в новую рабочую область
C:\Python314\python.exe scratch\edt.py -data 1c\perf-test\edt -command import `
  --version "8.3.27" --configuration-files 1c\perf-test\src `

# 2. Импорт расширения
C:\Python314\python.exe scratch\edt.py -data 1c\perf-test\edt -command import `

  --project 1c\perf-test\edt\PerfStyle --build true

# 3. Проверка (список - JSON-массивом в одной строке)
C:\Python314\python.exe scratch\edt.py -data 1c\perf-test\edt -command validate `
```

Отчёт `validate` - TSV с колонками: дата, важность, категория, проект, правило,
объект, место, описание.

## 6. Ограничения

- EDT 2026.2 понимает платформы до 8.5.1, поэтому обмен идёт через выгрузку 8.3.27
  (формат 2.20). Выгрузка 8.5.4 (2.22) даёт код 204.
- Платформы не зарегистрированы в реестре, поэтому EDT не знает установленных версий;
  на импорт и проверку это не влияет, но `start`/`infobase-*` не использовались.
- Проверка EDT дополняет `bsl-check`, а не заменяет: `bsl-check` (BSL LS) ловит
  синтаксис и часть стандартов, EDT - стандарты кодирования, обращения к платформе
  в разрезе клиентов и производительность.

### Ошибка, пойманная проверкой

После массовой замены «ё» отчёты перестали открываться:

```
{ОбщийМодуль.ПерфОтчетыHTML.Модуль(569)}: Ошибка при вызове метода контекста (Выполнить):
{(9, 4)}: Поле не найдено "Т.ВариантРазвертывания"
```

Причина: `Развёртывания` и `ОбъёмИБМб` - это имена измерений регистра
`ПерфСтенды`, заданные в метаданных. В `.bsl` они заменились на «е», а в XML
остались с «ё», и запросы перестали находить поля.

Возвращено 51 вхождение в 5 модулях, смоук снова 6/6. Оставшиеся 28 маркеров
`YoLetterUsage` - ровно эти идентификаторы: убрать их можно только
переименованием измерений в метаданных, а это миграция данных, а не правка текста.
