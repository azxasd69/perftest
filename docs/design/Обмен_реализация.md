## 4. Как устроена отправка

1. `ЗаписатьРезультат` → `ПоставитьВОчередьРезультат` → конверт `result` в регистр (в той же транзакции).
2. `ЗаписатьПаспортСтенда` (только при фактической записи, не при `passport-skip`) → конверт `passport`.
3. `СобратьИсториюВОчередь` — по команде или вызовом вручную: окна по 500 точек.
4. Отправка: `ОтправитьОчередь` → `ДоступныеКаналы()` (пробы моложе 15 минут и разрешённые) → `ПерфОбменТранспорт.ОтправитьПакет` перебирает каналы по приоритету; отказ приёмника (4xx кроме 429) не повторяется на другом канале.
5. Ответ: `200`/`207` с `items[]` → по каждому `id` статус `ok`/`duplicate` = `Отправлено`, иначе `Ошибка`; ответ без JSON при HTTP-канале = отказ (ловушка «живой статики»).
6. Неудача: `Ожидает` + пауза 1/5/15/60/300/900 с; после 12 попыток — `Ошибка`.
7. Ступень 2: `ВыгрузитьВСпул` пишет `<id>.json` (через `.part`), помечает конверт `ПризнакУтилиты`; `ПрочитатьПодтверждения` читает `out/<id>.ack`.

Триггеры без участия человека: старт сеанса (очередь непуста), после автопрогона (синхронно), таймер кокпита раз в минуту (`ОтправитьОчередьЕслиПора`, без второго задания), при завершении работы (лимит 10 с). Кнопки — диагностика.

### 5.1. Регламентное задание: причина прежней ошибки и как проверено

Рукописный XML не грузился: «Имя метода должно быть задано» + «Ссылка на неизвестный метод».
Причина выяснилась, когда задание создали в Конфигураторе и выгрузили платформой: **`MethodName`
пишется с префиксом вида объекта**:

```xml
<MethodName>CommonModule.ПерфОбмен.РегламентнаяОтправка</MethodName>
```

Без `CommonModule.` загрузчик считает имя пустым. Проверялось и с новым методом, и с существующим
(`ПерфСценарии.ТекущиеМс`) — поэтому и выглядело ограничением платформы. Правило на будущее:
канонический XML любого объекта, созданного руками, берётся **только из выгрузки платформы**.

Два следствия для развёртывания:

1. **Расписание — данные базы, а не метаданные**: в выгрузке нет элемента `Schedule`. Поэтому
   `ОбеспечитьРегламентноеЗаданиеОбмена()` создаёт экземпляр сам (период 15 минут) при старте сеанса
   и в режиме настройки; повторный вызов ничего не меняет.
2. **В файловой ИБ планировщик работает, пока открыт сеанс.** Проверено живьём: период выставлен
   60 с, сеанс держался 100 с — сработал запуск `exchange-schedule:13:0` (метод
   `ПерфОбмен.РегламентнаяОтправка` отправил 13 конвертов, очередь обнулилась).

Диагностика: `/C "ПерфОбменЗадания"` — состояние заданий (имя, включено, расписание, последний
запуск); `/C "ПерфОбменЗадания:60"` — поставить период 60 секунд и проверить срабатывание.

## 8. Грабли, которые стоит помнить

1. **Модуль общего модуля компилируется целиком при первом обращении**: одна несуществующая конструкция (`Новый ИнтернетПочтовоеВложение`) валит весь обмен, а не только почтовый канал. Отчёт платформы даёт строку и колонку — этого достаточно, чтобы найти место.
2. **Имя свойства и имя метода коллекции — разные вещи**: у `ИнтернетПочтовоеВложение` нет конструктора, вложение создаётся `Вложения.Добавить(Данные, Имя)`.
3. **Присваивание в структуру без `Вставить` не работает** — «Поле объекта не обнаружено».
4. **Фоновое задание не переживает `ЗавершитьРаботуСистемы`** — досылка в конце прогона должна быть синхронной.
5. **Разность дат в 1С — секунды**, поэтому троттлинг «раз в минуту» пишется как `< 60`, а не `< 1/1440`.
6. **`ЗаписатьБезОбработки` не ставит запятые** в массиве — разделитель пишем сами (иначе `400 bad_json`).
7. **Каждое новое метаданное — свой uuid во всех `TypeId`/`ValueId`**: копирование XML соседнего объекта даёт «Тип порождаемый объектом InternalInfo содержит не уникальное значение».

## 6. Фоновая проверка доступности каналов

Проба каналов выполняется фоновым заданием (`ПерфОбмен.ПробаКаналовЗадание`,
ключ `ПерфОбменПроба`) и запускается в двух точках:

| Точка | Кто вызывает | Когда |
|---|---|---|
| Старт сеанса | `ManagedApplicationModule.ПриНачалеРаботыСистемы` | после создания каналов и экземпляра регламентного задания, каждый запуск |
| Кнопка «Запустить все» | `НачальнаяСтраница.КомандаЗапуститьВсе` → `ЗапуститьПробуКаналовНаСервере` | в момент нажатия, параллельно с первым замером |

Правила:

- повторный запуск поверх активного задания не создаётся: проба перезаписывает
  регистр `ПерфОбменПроба` целиком, две параллельные пробы затирали бы записи;
  проверка — `ПолучитьФоновыеЗадания(Отбор)` по ключу и состоянию;
- перед пробой вызывается `ОбеспечитьКаналы()`: без записей каналов проверять нечего;
- проба идёт по **всем** девяти каналам, включая выключенные: администратору нужно
  видеть, жив ли канал, прежде чем включать. Выключенный канал не попадает в
  лестницу отправки — её строит `ДоступныеКаналы` по `Разрешён` + `Доступен` + `ГоденДо`;
- у пробы короткий таймаут (5 с) вместо 30 с отправки: молчащий порт иначе держит
  фон десятки секунд (8443 давал 42 с, стало 10 с — два уровня, с проверкой и без);
- результат: записи `ПерфОбменПроба` (9 строк) и маркер `probe:rows=9;ok=N` в
  `%TEMP%\perftest_marker.log`; факт запуска — `probe-run:<УИД>` или `probe-skip`.

Замеры проба не задерживает: она фоновая, сеть вне транзакции замера.

| `ПроверитьКаналыФон()` не вызывался ниоткуда | метод объявлен, точек запуска не было | добавлены старт сеанса и кнопка «Запустить все» |
| Проба наследовала таймаут отправки 30 с | `ОткрытьСоединение` читал таймаут только из константы | необязательный параметр `ТаймаутСекунд` в цепочке `ВыполнитьЗапрос → ВыполнитьЗапросУровня → ОткрытьСоединение`, проба просит 5 |

Проверено на копии (8.3.27): при старте сеанса `probe-run:<УИД>` и через 24 с
`probe:rows=9;ok=5`; клик по «Запустить все» даёт в `pf-cockpit.log` строку
«проба-каналов: запущена <УИД>», повторный вызов печатает «уже выполняется».
Живые каналы на стенде: HTTPS, HTTP80, PROXY, WEBDAV, SFTP — отвечают 200.
SMTP проверен частично: профиль строится, но подключение к 192.0.2.10:587 даёт
«Недопустимое значение параметра (параметр номер '2')» — нужен реальный SMTP-стенд.

## 7. Путь «Запустить все»: что происходит фактически

Проверено по коду 1.35 и живыми кликами.

| Шаг | Код | Факт |
|---|---|---|
| Кнопка | `ПерфКокпит.СкриптКокпита`, `PF1C.all()` | `lock(true)` + `send('all')`; блокировка снимается в `PF1C.done()` **после каждой карточки** |
| Приём | `НачальнаяСтраница.ОпросМоста` (0,25 с при прогоне, 2 с в покое) → `ОпросМостаШаг` → `ВыполнитьКомандуКокпита` | команда `all` попадает в `КомандаЗапуститьВсе` |
| Подготовка | `КомандаЗапуститьВсе` | guard от повторного запуска, запуск фоновой пробы каналов, очистка `Результаты`/`Сводка`, очередь из непустых `СцNИмя` (жёстко 1…11) |
| Карточка | `ЗапуститьКарточку` → `ПерфПаспорт.Обеспечить(Стенд, Паспорт, 0.5)` | если паспорта нет — синхронно пишется только быстрая фаза (без WMI), затем прогон |
| Прогон | `СтартПрогона` → `ПерфСценарии.ЗапуститьСценарийФон(Имя, 0, 10)` | третий параметр — чанков, 0 — порция из каталога; возвращается УИД задания |
| Опрос | `ОпросПрогрессаФон` каждые 0,3 с | однократный обработчик с переподключением (платформа не даёт период < 1 с), разбор `РЕЗУЛЬТАТ:` и `Чанк` |
| Повторы | `ЗавершитьПрогон` | при `ОрчПрогон < Повторов` — снова `СтартПрогона`; по умолчанию 2 прогона на карточку |
| Запись | `ЗавершитьКарточку` → `ЗаписатьРезультат` | `ПерфРезультаты`, паспорт стенда, `ПерфИстория`, конверт `result` в очередь; затем следующая карточка |

### Что в прежнем описании было неверно

1. **«Всё в той же транзакции»** — транзакции нет. `НачатьТранзакцию` в
   `ЗаписатьРезультат` отсутствует (единственная транзакция в конфигурации — внутри
   сценария «запись в транзакции», это сам замер). Результат, паспорт, история и
   конверт пишутся четырьмя независимыми записями. ТЗ § 12.1 требует атомарности
   «замер + конверт»; это расхождение остаётся (см. § 7.1).
2. **«Сети в этом пути нет вообще»** — сеть есть: при старте сеанса идёт досылка
   очереди, с 1.34 при нажатии кнопки запускается фоновая проба каналов, а таймер
   панели раньше запускал автодосылку и во время прогона.
3. Пропущен цикл повторов: одна карточка — это `Повторов` прогонов (по умолчанию 2),
   `ЗавершитьКарточку` вызывается только после последнего.
4. Не сказано, что при аварии фонового задания очередь останавливается целиком
   (`ОстановитьОчередьОшибкой`) — остальные карточки не выполняются.
5. «11 карточек» — число зашито: цикл в `КомандаЗапуститьВсе` и построение страницы.

### 7.1. Дефекты, найденные при проверке

| Дефект | Как проявлялся | Состояние |
|---|---|---|
| Повторная команда `all` во время прогона | `ОрчОчередь` перезаписывалась, `ОрчУИДЗадания` обнулялся: запускался второй замер той же карточки, первый продолжал работать, его результат никто не забирал (двойная нагрузка искажала медианы) | **исправлено**: guard по непустым `ОрчУИДЗадания`/`ОрчОчередь`, статус «Прогон уже идёт». Проверено кликом: второй клик даёт «запуск-все: отклонён, прогон уже идёт» |
| Автодосылка во время прогона | опрос идёт раз в 0,25 с, порог 30 тиков — отправка пакета каждые 7,5 с параллельно замерам; в файловой ИБ фон исполняется в том же процессе | **исправлено**: пока `ОрчУИДЗадания` не пуст, автодосылка не запускается. Проверено маркерами: за прогон ни одного `exchange-channel`/`exchange-sent` |
| Нет атомарности «результат + конверт» | сбой между записями оставлял замер без конверта | **исправлено (1.36)**: `НачатьТранзакцию` вокруг записи результата и постановки в очередь, паспорт и история — после; при исключении `ОтменитьТранзакцию` и повторная запись результата без конверта, чтобы недоступность сайта не теряла измерение |
| Проба каналов при «Запустить все» | стартовала одновременно с первым замером, а в файловой ИБ фоновое задание делит процесс с замером | **исправлено (1.36)**: нажатие планирует пробу (`ПробаПослеПрогона`), она стартует сразу после последней карточки; если карточек нет — сразу. Проверено: `probe:rows` идёт после последнего `exchange-queued:result` |

## 8. Плитки доступности каналов на карточке стенда (1.37, 09.11.2026)

На странице «Стенд» под блоком «Рабочее место (клиент)» две плитки `span-6`:
«Доступность каналов с сервера» и «Доступность каналов с клиента». Источник —
`РегистрСведений.ПерфОбменПроба`; плитки различаются измерением `Узел`.

| Что | Как |
|---|---|
| Состав каналов сервера | `ПерфОбменТранспорт.ВсеКаналы()` — все девять |
| Состав каналов клиента | `ПерфОбмен.ПараметрыПробыКлиента().Каналы` — только проверяемые с рабочего места (HTTPS, HTTPS8443, HTTP80, WEBDAV; PROXY — если прокси настроен) |
| Колонки | Приоритет (`БазовыйПриоритет`), Канал (+ краткая причина отказа), Мс, Код, Отметка |
| Отметки | `в работе` (включён и отвечает), `выключен` (отвечает, но выключен в настройках), `недоступен`, `нет пробы` |
| Подзаголовок | «N из M [проверенных] · проба ЧЧ:ММ», при истёкшем `ГоденДо` — «устарела» |
| Подвал | «проверено: <Откуда> · включено N из M» + пояснение состава для клиентской плитки |

Оформление — только существующие строители: `section.tile.tile-flat.span-6`,
`div.log-head`, `div.tw` + `ПерфUI.Таблица`, `ПерфUI.Бейдж`, `div.foot`. Новых
правил CSS и нового JS в версии 1.37 нет: кнопка пробы — `button.btn` с
`data-pf='send:probe'`, ветка `probe` в существующем `ОпросМостаСтенда`.

### Проба с рабочего места

`ПерфПробаКлиент` (клиентский общий модуль) выполняет те же GET-запросы, что и
серверная проба, но из клиентского процесса: видно, доходит ли приёмник с этой
машины (прокси, файрвол, VPN). Запуск — кнопка «Проверить каналы» в шапке
страницы; служебный режим — `/C "ПерфПробаКлиента"` (открывает страницу с
параметром `ПробаКлиента`, форма выполняет пробу и закрывается, итог — маркер
`probe-done:<N|none>`).

Запись — `ПерфОбмен.ЗаписатьПробуКлиента` → `ПерфОбменТранспорт.ЗаписатьПробы`
с узлом «Клиент»: `Откуда = "клиент <ПК>"`, `Процесс = 1cv8/1cv8c` (по
`СистемнаяИнформация.ТипПлатформы`).

### Разделение узлов (важно)

`ЗаписатьПробы` пишет **по одной записи на канал** через `СоздатьМенеджерЗаписи`
(ключ Узел+Канал). Набор записей с `Отбор.Узел` для этого не годится: проверено
09.11.2026 — проба сервера стирала строки клиента, потому что `Записать(Истина)`
замещал весь набор. `ДоступныеКаналы()` (лестница отправки) и таблица каналов в
журнале обмена читают только `Узел = "Сервер"`.

### Грабли версии 1.37

1. `ЗначениеЗаполнено(Ложь)` возвращает **Истина** (Булево всегда «заполнено»):
   защита вида `Если ЗначениеЗаполнено(ПробаИдёт) Тогда Возврат` глушит пробу
   целиком. Правильно — `ТипЗнч(ПробаИдёт) = Тип("Булево") И ПробаИдёт`.
2. `ТипПлатформы()` в клиентском общем модуле недоступен (ошибка 20:02:05):
   тип берётся из `СистемнаяИнформация.ТипПлатформы`.
3. Свойство у выражения `Новый X()` язык не принимает — «Ожидается символ ')'»
   (ошибка 10:08:14); нужна переменная.
4. Модальные `Предупреждение`/`Вопрос` в конфигурации запрещены: вызов бросает
   исключение, а исключения в обработчике `ПодключитьОбработчикОжидания`
   показываются только в журнале регистрации — снаружи выглядит как «ничего не
   происходит». Диагностику писать в `ПерфОшибки` (тяжесть «Событие») или
   маркером `ПерфСценарии.ЗаписатьМетку`.
5. Вызов клиентского общего модуля из `ПриНачалеРаботыСистемы` зависает:
   клиентский путь проверяется через форму (см. режим `/C ПерфПробаКлиента`).

### Кэш настроек каналов (1.38, 09.11.2026)

`ПерфОбменТранспорт.НастройкиКаналов()` читает регистр `ПерфОбменКанал` одним
запросом в `Соответствие` (Канал → Включен, БазовыйПриоритет, Защита). В циклах
используются `ПриоритетКаналаПоКэшу` и `КаналРазрешёнПоКэшу` — это убрало три
критических `query-in-loop` в EDT (запись проб, лестница отправки, задание
утилите) и сократило число запросов на пробу с 18 до 1. Логика разрешения
канала сохранена: запрет открытого FTP и учёт «Защита» из типовых настроек.

## 9. Переносимость: Linux и клиент-сервер (1.39, 09.11.2026)

База переносится через `.dt` и самодостаточна для основного сценария: в ней
лежат настройки обмена, токен и ключ HMAC (`ПерфОбменСекрет`), CA-сертификат
портала (`ПерфОбменСертификат`), девять каналов и все замеры. Вне базы остаются
файлы спула, файл секретов, внешние утилиты и настройки ОС.

| Механизм | Windows | Linux |
|---|---|---|
| Паспорт сервера | WMI (COM) | `/proc`, `/sys`, `/etc/os-release`; WMI-блок выключен планом сбора |
| Замеры, отчёты, карточка стенда | работают | работают (температурные ряды не используются) |
| Обмен по HTTPS | `HTTPСоединение` + CA из базы | так же |
| Клиентская проба каналов | HTTP из клиентского контекста | так же |
| FTP, SMTP, SFTP, DNS | `FTPСоединение`, `ИнтернетПочта`; `pscp` для SFTP | FTP/SMTP есть; `pscp` обычно нет — канал честно недоступен |
| CMS (`openssl`) | ищется через `where` | ищется через `which` |

### Что поправлено в 1.39

1. `ПерфОбмен.КаталогСекрета()` — разделитель пути берется из
   `ПолучитьРазделительПути()`; раньше жёсткая обратная косая давала на Linux
   путь вида `/var/lib/perf\obmen-secrets.json`, и спул с файлом секретов
   не находились. На входе допускаются оба разделителя.
2. `ПерфОбменТранспорт.ЕстьВPath()` — без `cmd`: `where` на Windows, `which`
   на Linux (добавлен `ЭтоЛинукс()` по `СистемнаяИнформация.ТипПлатформы`).
   Раньше на Linux функция всегда возвращала `Ложь`, из-за чего SFTP и
   CMS-путь считались недоступными даже при установленном `openssl`.
3. `ПерфОбменШифр.ВерсияOpenSSL()` — редирект вывода делает оболочка своей ОС
   (`sh -c` на Linux, `cmd /c` на Windows).
4. Самотест обмена печатает маркер `exchange-openssl:<да:версия|нет>` —
   переносимость видна без чтения кода.

### Остаточные ограничения (честно)

- Паспорт на Linux не содержит модель ПК, BIOS, диски, сеть, производителя и
  частоту ОЗУ: этих данных нет в `/proc`, а WMI недоступен. В карточке стенда
  это видно как «Что не собрано».
- На Linux-клиенте клиентский блок паспорта беднее (нет COM/WMI); имя
  компьютера собирается только вне веб-клиента (`#Если НЕ ВебКлиент`).
- Замеры файловой и клиент-серверной базы несопоставимы напрямую (другая цена
  записи и блокировок) — это методика, а не дефект.
- Служебные режимы `/C` в клиент-серверной базе запускаются с `/S<сервер>/<база>`
  вместо `/F`; скрипты `tools\ib.ps1` рассчитаны только на файловые базы.
- Реального прогона на Linux-стенде не было: выводы по коду и по гарантиям
  платформы 8.3.27.

## 10. Автоопределение среды и автонастройка (1.40, 09.11.2026)

При старте сеанса база сама определяет, где и как исполняется, и применяет
настройки, актуальные для этой среды. Новые объекты: `ПерфСреда` (серверный
общий модуль), `ПерфСредаКлиент` (клиентский), константа `ПерфПрофильСреды`.

### Что определяется

| Признак | Источник | Значения |
|---|---|---|
| Где исполняется серверный код | `РежимИнформационнойБазыСтрокой()` | «Сервер» / «Клиент (файловая ИБ)» |
| Вариант работы базы | тот же признак | «Файловая» / «Клиент-сервер» |
| ОС | `ПерфПаспорт.ОпределитьСреду()` | «Windows» / «Linux» |
| Платформа | `СистемнаяИнформация.ВерсияПриложения` | 8.3.27.2342 и т. п. |
| Режим клиента | `СистемнаяИнформация.ТипПлатформы` на клиенте | «Толстый» / «Тонкий» / «Веб» |
| Вариант запуска | строка `/C` | «Интерактив» / «Автопрогон» / «Служебный режим» |
| Возможности | проверка фактом | WMI, `/proc`, `pscp`, `openssl`, почта |
| Отпечаток | сводка | `win-file-thick`, `lin-srv-thin` |

### Правила профиля: только запреты

Автонастройка **не включает** каналы и **не меняет** адрес, порты, пути, токены
и сертификаты. Она выключает только то, что в этой среде заведомо не работает,
и пишет причину в `Примечание` канала с датой:

| Канал | Условие выключения | Примечание |
|---|---|---|
| `SFTP` | нет `pscp` в PATH | «авто ДД.ММ.ГГ: нет клиента pscp в PATH» |
| `HTTP80` | нет `openssl` (CMS обязателен) | «нет openssl для CMS» |
| `PROXY` | прокси не настроен | «прокси не задан» |
| `DNS` | всегда | «канал только утилитой perf-push» |
| `SMTP` | не заданы адреса отправителя/получателя | «не заданы адреса почты» |
| `FTP` | защита «нет» | «открытый FTP запрещен» |

Идемпотентность: выключаются только **включённые** каналы; уже выключенные не
перезаписываются, примечание администратора не стирается. Выключатель —
`ПерфПрофильСреды = "Выкл"` (по умолчанию пусто = авто включена).

### Где видно

- маркер старта: `env:<отпечаток>:off=<сколько выключено>`;
- применение: `env:apply:<отпечаток>:<N>`;
- запись в `ПерфОшибки` с тяжестью «Событие»: среда одной строкой + что выключено;
- страница «Журнал обмена»: блок «Среда запуска» (где код, база, ОС, платформа,
  WMI, /proc, pscp, openssl, профиль).

### Поведение по средам

| Среда | Что применяет |
|---|---|
| Windows, файловая, толстый клиент | не трогает ничего, если всё установлено; WMI и `/proc`-блоки решаются планом паспорта |
| Linux, сервер | выключает `SFTP` и `HTTP80`, если нет `pscp`/`openssl`; паспорт идёт по `/proc` |
| Клиент-сервер | то же; дополнительно в журнале видно «где код: Сервер» |
| Веб-клиент | клиентская проба каналов недоступна: кнопка объясняет причину и не запускает HTTP |

### Служебные режимы

- `/C "ПерфОбменПоле:<канал>:enabled:1"` — включить канал (для проверки правил);
- `/C "ПерфОбменПоле:<канал>:note:<текст>"` — примечание канала.
