вопросы верхнего уровня; детали остаются в разделах `spec/`, `design/`, `verify/`, `ops/`,
`decisions/`. Дублирования нет: системные документы ссылаются на детальные, а не пересказывают их.

## Как читать

- **Заказчику и приёмке** — 1, затем 4 (§9 «Состояние и проверки»).
- **Разработчику** — 2, затем 3; детали кода — в `../design/Реализация.md`.
- **Администратору** — 4, затем 3 (§8 «Развёртывание и эксплуатация»).
- **Новичку** — 1, 2, 4; 3 читается по мере необходимости.

## Как комплект сверялся с реализацией

Порядок был обратный обычному: не «требование → код», а **«код → документ»**. Источники, по которым
документы дозаполнены 11.11.2026:

| Источник | Что из него взято |
|---|---|
| `src/` (выгрузка 1.42) | точные размеры модулей и число экспортов, реквизиты 7 форм, поля 9 регистров, 11 констант с типами, свойства конфигурации, состав обработки и документа |
| модули `ПерфОбмен`, `ПерфОбменТранспорт` | механика очереди (19 реквизитов, 5 статусов, паузы 1…900 с, снятие зависших через 10 минут), лимиты тел 4/20/256 КБ, формат `id`, лестница каналов и проба |
| портал `tools/portal` | режимы `perfd`, `PERF_*`, таблицы и индексы, маршруты, порядок приёма конверта, коды `409`/`413`/`415` |
| `README.md` репозитория | ограничения движка HTML-поля и обходы, токены тем, геометрия меню, интервалы, цифры производительности, матрица «что где работает», ограничения обмена |
| `CHANGELOG.md` | привязка стадий к версиям, история по версиям |

Найденные расхождения (не «поправлены молча», а зафиксированы в документах):

| Что | Состояние |
|---|---|
| Подпись HMAC | ставится отправителем, приёмник её **не проверяет**; README портала обещает проверку |
| Предел 12 попыток | в коде не ограничен: конверт повторяется каждые 900 с бесконечно |
| CMS-шифрование | фактически только для SMTP, для HTTP80 — лишь проверка наличия `openssl` |
| Обратный канал команд | не реализован (`cmd_queue` есть, обработчика нет) |
| Подтверждения по IMAP | не читаются, только локальные `out/<id>.ack` |
| Утилита отправки DNS и спула | в репозиториях отсутствует |
| `CHANGELOG.md` | было две записи `1.28` — объединены в одну |

## Правила ведения

1. Системные документы обновляются при изменении **границ, решений или состояния**, а не при каждой
   правке кода: мелкое изменение идёт в детальный документ и `CHANGELOG.md`.
2. Шапка обязательна: тип, статус, версия сверки, дата ревизии, вопрос.
3. Числа (размеры, число реквизитов, лимиты) берутся из кода и пересчитываются, а не переносятся из
   прошлой версии документа.
4. Диаграммы — в Mermaid (отображается на GitHub) или текстовыми схемами; PNG-файлы не добавляются,
   чтобы не расходиться с текстом.
5. Реальные адреса, домены и токены не публикуются: только плейсхолдеры.
6. Внешние стандарты указываются ссылками и используются как основа структуры, их текст не
   копируется.

## Основание

Структура: [ГОСТ 34.602-2020](https://www.swrit.ru/doc/gost34/34.602-2020.pdf) (ТЗ на АС, с
01.01.2022 вместо 34.602-89), [ISO/IEC/IEEE 29148:2018](https://www.iso.org/standard/72089.html)
(свойства требования), [arc42](https://arc42.org/overview) (разделы архитектуры),
[C4](https://c4model.com/diagrams) (уровни диаграмм), [ADR](https://adr.github.io/) (фиксация
решений).
