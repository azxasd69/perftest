Паспорт системы отвечает на эксплуатационные вопросы: что установлено, где лежит, чем проверено,
что сломается и что делать. Он не заменяет техническое задание (что требуется) и техническое
решение (почему сделано так). Паспорт **стенда** — другой документ: это автоматически собранные
сведения о среде замера, они хранятся в регистре `ПерфСтенды` и описаны в
`../design/Паспорт_стенда.md`.

## 2. Назначение и область применения

Система измеряет скорость типовых операций 1С на конкретной машине, сборке платформы и режиме
клиента, сохраняет замеры, строит сравнения и передаёт результаты на портал для общей витрины.
Применение: проверка «стало ли быстрее» после смены платформы, настроек сервера или диска; сравнение
стендов между собой; накопление истории замеров.

Область применения ограничена: файловая информационная база, настольные клиенты, синтетические
сценарии. Аттестация оборудования и воспроизведение прикладной нагрузки в область не входят.

## 5. Установка и запуск

```powershell
# конфигурация: создать базу, загрузить выгрузку, проверить модули
pwsh -File tools\ib.ps1 -Action create -Base <каталог ИБ> -PlatformVersion 8.3.27.2342
pwsh -File tools\ib.ps1 -Action load   -Base <каталог ИБ> -Dir src
pwsh -File tools\ib.ps1 -Action check  -Base <каталог ИБ>

# расширение оформления
pwsh -File tools\ext-load.ps1 -Base <каталог ИБ>

# автопрогон 11 сценариев и смоук форм
1cv8.exe ENTERPRISE /F<каталог ИБ> /C"ПерфАвтоПрогон;;0;1"
1cv8.exe ENTERPRISE /F<каталог ИБ> /C"ПерфСмоукФорм"
```

```bash
# портал
PERF_DB=/var/lib/perf/perf.db \
PERF_INGEST_TOKEN_SHA256=<хеш токена> \
PERF_HMAC_KEY=<ключ> \
PERF_BASE_PATH=/perf \
perfd -addr 127.0.0.1:8080
```

## 10. Ограничения и известные проблемы

| Ограничение | Влияние | Обход |
|---|---|---|
| Файловая ИБ: фон и замер в одном процессе | автодосылка во время прогона искажает числа | отправка не запускается при активном прогоне |
| Каналы 2–8 не проверены вживую | возможно ложное «канал работает» | проба каналов и журнал обмена, профиль среды выключает заведомо нерабочие |
| Нет автоматического бэкапа портала | потеря базы при отказе диска | ручной `perfd -export` (ответственность владельца) |
| Клиент-серверная ИБ проверена частично | неизвестны ограничения на больших объёмах | отдельный прогон перед переводом в эксплуатацию |
| Паспорт на Linux без WMI | часть реквизитов пуста | причина пишется в замечаниях сбора |
| Замечания EDT: запросы в цикле | потенциальная деградация | принято осознанно для сценариев замера |
| Максимум один сервер портала | нет резервирования | снимок базы и быстрый перенос на другой сервер |

## 11. Сопровождение

| Задача | Регламент |
|---|---|
| Изменение поведения | правка в `src`, загрузка в копию базы, гейты, живой прогон ключевых страниц |
| Выпуск версии | `CHANGELOG.md` + версия в `Configuration.xml` + тег `v*` + релиз на GitHub |
| Обновление портала | сборка по тегу, атомарный релиз каталогом, откат на предыдущий каталог |
| Ротация токена | новый хеш на портале и новый секрет в базе 1С, затем проверка пробой |
| Диагностика обмена | журнал обмена (состояние, каналы, очередь), маркеры `exchange-*`, `/healthz/channels` |
| Диагностика замера | маркеры `ok:`, `reg-rows`, журнал ошибок, повторный прогон |

Точки отказа: лицензия 1С (без неё нет сеанса), файловая ИБ (порча файла базы), сеть до портала
(очередь растёт, но замеры сохраняются), диск портала (нет бэкапа — критично).
