# Документация PerfTest

Точка входа в документацию. Правило одно: **если документа нет в этой таблице, его для проекта
не существует**. Новый файл добавляется сюда тем же коммитом, иначе падает `check-doc-index.py`.

## Как искать

| Вопрос | Раздел |
|---|---|
| «Что должно быть?» | [`spec/`](spec/) — требования и границы |
| «Как это сделано и почему?» | [`design/`](design/) — устройство, решения, ограничения |
| «Чем это подтверждено?» | [`verify/`](verify/) — прогоны, гейты, остаточный риск |
| «Что в регистрах и полях?» | [`data/`](data/) — схема данных |
| «Что делать, если…?» | [`ops/`](ops/) — эксплуатация и диагностика |
| «Почему решили именно так?» | [`decisions/`](decisions/) — ADR |
| «Как это выглядит?» | [`refs/`](refs/) — прототипы, скриншоты, варианты логотипа |
| «Как было раньше?» | [`archive/`](archive/) — замороженные документы |

## Статусы

| Статус | Значение |
|---|---|
| `черновик` | пишется, как источник истины не читать |
| `актуален` | сверен с кодом на версии из шапки |
| `отстаёт` | код ушёл вперёд, сверка нужна (в шапке — на какой версии сверяли) |
| `архив` | не поддерживается, лежит в `archive/` |

## Регламент (кратко, полностью — `CONTRIBUTING.md`, этап 5)

1. Правка поведения → строка в `CHANGELOG.md` + правка тела документа (не новый раздел в конце).
2. Новая версия → новая секция CHANGELOG, шапки обновляются там, где сверяли.
3. Документ без строки в этом индексе — ошибка CI (`check-doc-index.py`).
4. Ссылки — относительные внутри репозитория.
5. Секреты, адреса и токены в документы не попадают.
